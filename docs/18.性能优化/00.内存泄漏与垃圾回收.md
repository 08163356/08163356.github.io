## 实践结论

- DOM 节点只增不减，优先查事件、定时器、全局缓存和 Vue 组件是否没卸干净。详见 [domNode 一直增加](/pages/8a302d/)、[泄漏原因](/pages/872054/)、[记一次内存一直增长](/pages/4cdf9c/)。
- 用 DevTools Memory + heap snapshot 对前后两次快照。见 [如何用 devtool 分析](/pages/06b005/)、[memory 用法](/pages/f7d444/)。
- GC：搞清 GC Root 和 JS 内存模型后再看 Vue 里频繁 new 对象。见 [JS 垃圾回收](/pages/13a64c/)、[内存模型](/pages/d216ed/)。
- Vue 里少在模板热路径创建临时对象、大数组用对象池或复用，避免渲染一轮就触发一次 GC。

## 从碎片收进来的要点

- iframe 打包后路径找不到：构建 `base` 和 iframe 的 `src` 要同一套 publicPath，不要写死相对目录。
- SSE 推流过密会卡住主线程，见 [SSE 导致卡顿](/pages/f1b5bf/)。
