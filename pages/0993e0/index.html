什么是事件循环

JS本身是单线程运行的，为了不阻塞主任务的执行，将任务区分成了诸如（IO、脚本加载、文件加载、UI渲染、事件回调）等宏任务和诸如（nexTick、promise）等微任务。v8中有一个关于任务的执行栈，通常的运行顺序是：

主线程任务——>微任务——>宏任务 如果宏任务里还有微任就继续执行宏任务里的微任务，如果宏任务中的微任务中还有宏任务就在依次进行
主线程任务——>微任务——>宏任务——>宏任务里的微任务——>宏任务里的微任务中的宏任务——>直到任务全部完成 我的理解是在同队列下，微任务要优先于宏任务执行

宏任务与微任务汇总

任务类型任务名称描述
宏任务整体代码执行脚本的初始执行
宏任务setTimeout延迟执行的回调函数
宏任务setInterval定期执行的回调函数
宏任务I/O 操作文件读写、网络请求等异步操作
宏任务UI 渲染浏览器的绘制和重排任务
宏任务事件回调用户交互事件（如点击、输入等）的处理
微任务Promise 的 then 和 catch处理 Promise 的结果
微任务MutationObserver观察 DOM 变更的回调
微任务queueMicrotask手动添加微任务到微任务队列
微任务async/await使用 await 的异步操作后续处理

为什么先执行宏任务后执行微任务

确保执行环境的一致性。因为渲染、IO、文件读写、脚本加载等宏任务是在微任务之前执行的，如果将微任务放到上述的宏任务之后执行，那么上下文就会改变，得到的结果会和预期不一致

微任务在遇到内部事件循环的时候会出现栈溢出的现象，因为微任务只有执行到任务的"}"时，才会将任务的内存释放，如果内部循环，则内存会无法释放导致溢出

宏任务和微任务不同，他是执行完立马会出队列，而不需要一定要走到最后的“}，因此不存在栈溢出。

async function async1() {
  console.log("async1 start");
  await async2();
  console.log("async1 end");
  setTimeout(() => {
    console.log('timer1')
  }, 0)
}
async function async2() {
  setTimeout(() => {
    console.log('timer2')
  }, 0)
  console.log("async2");
}
async1();
setTimeout(() => {
  console.log('timer3')
}, 0)
console.log("start")

输出

async1 start
async2
start
async1 end
timer2
timer3
timer1

关键步骤解析：

  1. 同步代码执行阶段：

    • 执行async1()立即输出async1 start

    • 进入

      await async2()

      ：

      • 执行async2()内部的setTimeout将timer2加入宏任务队列
      • 同步输出async2

    • await让出主线程，后续代码包装为微任务

    • 主线程继续执行：

      • 将timer3加入宏任务队列
      • 同步输出start

  2. 微任务阶段：

    • 执行

      await

      后的代码：

      • 输出async1 end
      • 将timer1加入宏任务队列

  3. 宏任务阶段：

    • 按入队顺序执行：
      1. 第一个setTimeout回调 → 输出timer2
      2. 主线程的setTimeout → 输出timer3
      3. 微任务中新增的setTimeout → 输出timer1

深层原理：

  • await本质是将后续代码包装为Promise.then()的微任务;await 后的代码作为微任务，优先于宏任务执行。
  • 事件循环优先级：同步代码 > 微任务 > 宏任务
  • 同类型任务按入队顺序执行，timer2比timer3更早加入宏任务队列

通过这个案例可以清晰理解JavaScript事件循环中不同任务类型的执行优先级和顺序。

async function async1 () {
  console.log('srcipt start');
  await new Promise(resolve => {
    console.log('promise1')
  })
  console.log('async1 success');
  return 'async1 end'
}
console.log('srcipt start')
async1().then(res => console.log(res))
console.log('srcipt end')

输出：

'srcipt start'
'async1 start'
'promise1'
'srcipt end'

如果await后跟随的是async声明的函数，则一定会继续async1 success和async1 end，但因为new Promise没有resolve，所以后续代码无法继续执行。

await接收的函数只有存在返回值的情况下才会执行后续的代码，不然会进行截断，代码会在await处结束。
